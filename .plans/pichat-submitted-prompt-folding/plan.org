* Goal
Keep long submitted user messages compact in the chat buffer, matching the Jobs details instruction disclosure, without making draft editing surprising or changing messages sent to Pi.

* Scope
- Included: shared visual-line measurement and disclosure mechanics where appropriate; folding ordinary submitted user messages in the live tail and canonical transcript; interaction, resize, source-scoped state, copy behavior, tests and user documentation.
- Included: review coexistence with skill-message folding and image/text messages without hiding attachment indicators.
- Excluded: automatic or manual draft folding, a capped/scrolling input viewport, assistant-response folding, changes to submission/queue semantics, saved-session persistence of fold preferences, and unrelated Jobs redesign.

* Acceptance criteria
- Drafts remain fully expanded while typing, pasting, recalling history, restoring fork text, recovering submissions, and applying the compose editor. Completion, newline/send keys, selection and undo retain their existing behavior.
- Ordinary user messages exceeding five visual lines default to a five-line preview ending in an ellipsis; short messages have no disclosure. Both wrapped lines and explicit newlines count, including the bar/prefix and indicator width.
- RET/TAB or click in a read-only disclosure toggles it; expanded long messages offer Show less. Draft keybindings are unaffected, including graphical/terminal TAB and optional Evil behavior.
- Only authoritative Pi user-message events create transcript messages. Submission failure never leaves a fabricated folded message and restores full editable text under the existing recovery rules.
- Explicit expansion choices survive streaming, settlement, same-source repaint and resize; source rebinding resets choices. Resize does not edit the draft, pollute undo or unexpectedly move point/scroll.
- Skill invocation disclosure remains intact without nested competing folds. Mixed image/text handling keeps attachment information visible and does not lose source content.
- Full-message copying is explicit and copies the original message rather than the preview. Canonical export and saved session files are unchanged. Ordinary region-copy behavior is documented accurately for the chosen presentation mechanism.
- Jobs details retain their current five-visual-line behavior and explicit-choice preservation after shared-code extraction.
- Focused behavior tests and pichat/test/run-tests.sh pass; a separate isolated live Emacs check covers wrapping, resize, disclosure keys and draft editing. Required manual checks remain actionable until actually verified.

* Approach and decisions
- Reference terminology: pichat/GLOSSARY.md (draft, live tail, canonical transcript, settlement, source rebinding).
- pichat/pichat-jobs.el: pichat-jobs--insert-instructions currently inserts full instructions, measures with vertical-motion in the narrowest displaying window, deletes the hidden display suffix, and rebuilds details on toggle/resize. Reuse measurement/indicator logic, not whole-view reconstruction or Jobs-owned state.
- pichat/pichat-render.el: pichat-render--node-fragment renders ordinary user blocks; pichat-render--skill-user-fragment already supports compact skill headers.
- pichat/pichat-chat.el: skill view state/toggle logic supplies an existing identity and repaint pattern; live-input styling and prompt markers must stay independent of read-only folding.
- pichat/pichat-chat-input.el: submission clears the draft before backend submission and restores/recoverably retains failures. Preserve this behavior; do not create optimistic local user transcript nodes.
- Extract a small presentation helper with explicit inputs and no implicit chat/Jobs state dependency. Keep window-dependent measurement outside the pure canonical renderer.
- Prefer non-destructive chat presentation overlays, subject to checking projection transactions, rollback, fragment equality and overlay lifecycle. Do not blindly truncate projected transcript strings or reuse the Jobs deletion approach.
- Key chat choices by source-scoped message identity and validate original content; explicitly reconcile live-to-canonical identity during settlement rather than assuming node keys match. Do not reprojection-edit the draft on every keystroke.
- Default policy: drafts always expanded; long submitted messages, including the newest, folded. Use the narrowest displayed width consistently with Jobs; preserve explicit expanded/collapsed choices as width changes.
