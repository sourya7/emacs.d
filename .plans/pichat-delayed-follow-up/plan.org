* Goal
Let a user schedule one opt-in, Emacs-owned continuation for the exact owning PiChat chat: either prompt with =continue= after a delay, or compact successfully and then prompt. Fail closed if ownership or conversation state changes; never silently queue work in another Pi session.

* Scope
- Included: bounded relative-duration scheduling, status/replacement/cancellation controls, source- and process-safe dispatch, tests, and documentation.
- Excluded: automatic quota/reset detection, account switching, daemon or persistent jobs, silent recovery after restart, exactly-once guarantees on lost RPC responses, and changes to Pi's immediate follow-up queue.
- Design provenance: [[file:legacy/pichat-delayed-follow-up-plan.md][imported full proposal]] (original: [[file:../../.tmp/pichat-delayed-follow-up-plan.md][.tmp proposal]]). This Org record alone owns future task status; the legacy copy is reference material, not an execution tracker.

* Acceptance criteria
- A live, idle, synchronized Pi-backed chat can schedule, inspect, replace with confirmation, and cancel at most one delayed job; the unsent draft and attachments remain unchanged.
- A job fires no earlier than its due time and submits one normal prompt only after verifying exact chat/runtime, Pi session, source/process generations, active branch, model, and idle/empty-queue state. A source switch, restart, intervening work, busy state, lost ownership, or ambiguous RPC outcome must not cause an unintended prompt.
- Compact-then-continue prompts only after correlated successful compaction and renewed same-source/idle validation; failed or ambiguous compaction never prompts.
- ERT and isolated real-Pi fake-provider tests cover timers, cancellation, rebinding, stale callbacks and the ordering of compaction and continuation; =pichat/test/run-tests.sh= and =pichat/test/run-tests.sh --full= results are recorded. Document controls and Emacs-lifetime limitations using terminology from =pichat/GLOSSARY.md=.

* Approach and decisions
- On import, inspected =pichat-chat-follow-up=, =pichat-chat-compact=, status/source-token helpers and existing RPC functions; no =pichat-chat-schedule= or =pichat-chat-cancel-schedule= definition found. This is an unimplemented proposal, not previously completed work.
- Follow the full legacy design for proposed state machine, ownership checks, error handling and verification matrix. Recheck Pi RPC and PiChat APIs when execution is requested; importing does not approve or implement the design.
- Use Emacs one-shot timers and existing PiChat RPC/backend operations; a Pi =follow_up= is an immediate post-run queue, not a delayed schedule. Preserve the distinction between runtime, Pi session and saved session file per =pichat/GLOSSARY.md=.
