Address the reviewed PiChat maintainability and correctness findings through bounded, independently selected work packages without weakening runtime, source, transcript or draft safety.

** Shared completion requirements

These apply to every package in addition to its own checklist:

- Keep scope bounded; record discoveries that need separate work as new packages.
- Add durable behavioral tests for changed behavior, not assertions that merely
  reproduce the old defect. Temporary review probes are supporting evidence only.
- Run relevant checks from the testing guidelines. For package changes, run
  =pichat/test/run-tests.sh=; use =--full= for affected real-Pi contracts when the
  required environment is available. Record skips and unavailable verification.
- Never claim an unavailable required check passed. Leave acceptance incomplete
  unless the maintainer explicitly approves a narrower verification scope.
- Record commands, results, environment/version where relevant, and limitations
  beneath the package. Keep verbose logs in =.tmp/=, durable tests in the suite.
- Add a brief resolution note to the corresponding review finding: resolved,
  partially resolved, deferred, or not pursued; describe the evidence and scope.
  Preserve original observations as historical evidence rather than erasing them.
- Record commit references only if commits are subsequently made. Do not copy
  the whole work log into the review or maintain a second checklist there.
