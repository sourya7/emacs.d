* Goal
Remove PiChat's blanket SSH reconfiguration restriction so a supported SSH runtime can replace its startup preset/Tools and reload its Pi session, while preventing a replacement from starting when old-process termination is uncertain.

* Scope
- Included: evidence-based SSH shutdown semantics, transport-aware restart eligibility and shutdown confirmation, complete SSH reconfiguration and recovery coverage, and user documentation.
- Preserve runtime identity, owner scope, captured SSH target/path context, run-local model, draft, canonical restart snapshot, and existing saved/unwritten Pi session semantics as defined in pichat/GLOSSARY.md.
- Excluded: changing ordinary launch/reuse policy, enabling ephemeral reconfiguration, arbitrary-wrapper support, remote reconnection/resumption, distributed session locking, or guarantees against unrelated external Pi writers. No commits or destructive network experiments without authorization.

* Acceptance criteria
- A persistent idle SSH runtime can change preset/Tools through the existing reconfiguration UI without a blanket transport blocker.
- A saved Pi session retains its ID, active branch, transcript and supported settings; an eligible unwritten session follows existing new-Pi-session-ID behavior.
- Runtime ID, owner scope, chat/draft and captured destination remain stable; no local execution fallback occurs.
- Replacement starts only after evidence tied to the old process establishes shutdown. Disconnection, probe failure, timeout, stale callback or cancellation cannot be mistaken for successful termination.
- Failed post-stop attempts retain the read-only restart snapshot and support applicable retry/restore/leave-stopped actions without duplicate writers.
- Existing local behavior and other preflight guards remain intact.
- Unit suite, full real-Pi suite, and focused isolated real-SSH restart tests pass; live Emacs UI verification confirms the action is enabled and usable on SSH.

* Approach and decisions
- Relevant code: pichat/pichat-reconfigure.el (preflight-blockers, stop-and-wait and restart transaction), pichat/pichat-transport.el (TRAMP process creation), pichat/pichat-rpc.el (stop/sentinel/process generation), pichat/pichat.el (Transient menu/recovery).
- Current guards reject non-local transport both during preflight and shutdown. pichat-rpc-stop uses delete-process; the existing restart waiter checks Emacs process liveness and session state.
- Do not infer that SSH shutdown is broken from those guards. Inspect the installed Emacs/TRAMP implementation and relevant documented guarantees before choosing a mechanism.
- Prefer existing reliable TRAMP process identity/termination facilities if supported by evidence. If insufficient, add the smallest transport-owned identity and bounded exit-confirmation mechanism. Do not use a broad command-line pgrep pattern as production process identity or kill unrelated processes.
- Keep confirmation asynchronous/bounded and scoped to the captured transport, old process and process generation. A successful request to terminate is not automatically an exit confirmation. Account for PID reuse if using remote PIDs.
- Distinguish safe retry after confirmed shutdown from uncertain old-process survival; audit recovery as well as initial restart before enabling SSH.
- Existing source reservations are Emacs-local; this change does not promise protection against external writers.
